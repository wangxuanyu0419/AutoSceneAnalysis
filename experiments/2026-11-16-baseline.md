# First local photo baseline

Date: 16 November 2026. The photo-to-menu pipeline runs locally on this workstation. It produces an inspectable object list and a useful relative-depth preview, with roughly 0.43 seconds of repeated perception time on the RTX 2060. The output also contains clear recognition mistakes, so it is a starting point for an interaction inventory rather than an accurate catalogue of every object.

## Input and settings

The input is public COCO val2017 image 139, a 640 × 426 pixel living and dining room. Its URL is `http://images.cocodataset.org/val2017/000000000139.jpg`. The downloaded file SHA256 is `ffe0f0cec3b2e27aab1967229cdf0a0d7751dcdd5800322f0b8ac0dffb3b8a8d`. The image and generated previews stay outside Git; image rights remain with the original photographer.

The detector is Grounding DINO Tiny, with 14 room-oriented category prompts, box threshold 0.30, text threshold 0.25, and same-label duplicate suppression at IoU 0.60. Its shortest input edge is 640 pixels, with the longest edge capped at 960. Depth Anything V2 Small supplies relative inverse depth, using its aspect-preserving image processor with size setting 518. Both models run in float32 with four CPU threads.

## Measured runtime

| Device | Warmups excluded | Repeated samples | Median | p95 | Peak PyTorch allocated memory |
| --- | --- | --- | --- | --- | --- |
| NVIDIA GeForce RTX 2060 | 2 | 20 | 431 ms | 487 ms | 1,563 MiB |
| NVIDIA RTX A2000 12GB | 1 | 10 | 418 ms | 565 ms | 1,563 MiB |

Each timing covers image preprocessing, transfers, detection, detection postprocessing, and relative depth. CUDA is synchronized. Camera capture, scene assembly, report rendering, neural decoding, and robot control are outside that timing. PyTorch reserved about 1,858 MiB at peak; these allocator numbers exclude other processes and some driver overhead.

This is a small smoke test on one repeated image. The A2000 had other work resident, and the runs used different warmup counts. The table establishes that both cards can run this baseline in the observed conditions; it is not a controlled comparison of which card is faster.

Cold startup was quite different. The first A2000 run took about 95 seconds for model loading and downloads, then about 23 seconds for its first perception pass. On the later cached RTX 2060 run, model loading took about 1.45 seconds and the first pass about 2.38 seconds. Repeated speed therefore describes a running application, not time from a fresh install to a first result.

PyTorch enumerated the A2000 as `cuda:0` and the RTX 2060 as `cuda:1`, the reverse of `nvidia-smi` on this machine. The initial run used the A2000. The CLI now supports `--gpu-name` and prints the resolved device to avoid relying on the enumeration order.

## What the output gets right and wrong

Both runs retained 30 candidates after duplicate suppression. By visual inspection, the large left television, dining chairs, tables, and several cabinet regions are recognizable detections. The depth preview places the foreground table and vase nearer than the rear room, which is qualitatively sensible.

There are also instructive failures. The foreground green vase is labelled “bottle” with a score of about 0.32. A decorative vessel near the television is labelled “cup” at about 0.54. The fireplace on the right is labelled “television” at about 0.37. The prompt list does not include “vase,” and changing a category label also changes the rule-based action menu: a mistaken bottle label offers “open” for a vase.

This exposes an important dependency in the proposed framework. An object/action representation is only as useful as the object identity, part information, and state that feed it. Adding masks, broader candidate discovery, an explicit unknown option, and better action evidence are more valuable next steps than generating a prettier mesh.

These observations are visual diagnostics made after seeing the predictions. No held-out annotations or metric distance measurements were used, so this run supplies no precision, recall, or centimetre-error result.

## Reproduce or inspect

The generated RTX 2060 report is at `G:\AI\AutoSceneAnalysis\outputs\coco-rtx2060\report.html`. Its adjacent files include the scene, timing samples, input preview, object overlay, and raw inverse-depth array. The initial A2000 output is in `outputs\coco-baseline`.

```powershell
.\.venv\Scripts\python.exe scripts\run_demo.py --image data\samples\coco_000000000139.jpg --gpu-name "RTX 2060" --warmups 2 --repeats 20 --offline --out outputs\coco-repeat
```

The scene-contract tests cover duplicate handling, normalized coordinates, the absence of fabricated metre coordinates, empty detections, invalid depth, and conditional object/action vectors. Browser checks exercise the report's actual object selection, action selection, vector display, and cancel controls. A separate synthetic run checks the interface without loading models.

## Decision

The baseline is fast enough for occasional inventory refresh and a static two-axis interface. Around 0.43 seconds per full pass does not meet the proposed 200 ms target-age goal for an actively moving scene. Keep discovery separate from a faster tracking path, and compare a mask-producing detector next. The next scientific result should come from a labelled room-target set, including small parts and repeated objects.
